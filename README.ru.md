# Matryoshka MMI

**Добавьте пластичную постоянную память вашему кодинг-агенту.**

Матрёшка — перезаписываемый субстрат памяти: **память самой модели**, а не
обвязки агента. Агент ведёт рабочий процесс; **модель** решает, что запомнить
и что вспомнить: каждый акт памяти (запись, чтение, повтор) — акт самой модели
в её собственном выходном потоке. Агентская оболочка — лишь исполнительная
рука. Ваши инструменты продолжают работать — логи, RAG, векторные хранилища,
графы; Матрёшка добавляет личную память модели рядом с ними. Без
embedding-моделей, без внешних сервисов, без аккаунтов. Один Python-файл,
только стандартная библиотека.

Работает с **Claude Code**, **OpenCode** и **Prime Agent** (всё, что говорит
на MCP). Ваша модель, ваш ключ, ваша память — всё остаётся на вашей машине.

## Что делает установщик — точно

Всё происходит **на вашей машине, в вашем домашнем каталоге**. Ничего не
загружается, ничего никуда не отправляется, никакого удалённого аккаунта.

Прежде чем менять что-либо, установщик печатает список файлов, которые
затронет, и спрашивает подтверждение. Он только:

1. Создаёт `~/.matryoshka/` и кладёт туда два файла:
   - `mmi_mcp.py` — сервер памяти (локальная программа, ~8 КБ Python);
   - позже — ваши данные памяти: `PHI.jsonl`, `TICKS.log`.
2. Добавляет **одну запись** с именем `matryoshka` в конфиг каждого
   кодинг-агента, найденного **на вашей машине**, — только чтобы агент знал,
   что сервер памяти существует:
   - Claude Code: `~/.claude.json` → `mcpServers`
   - OpenCode: `~/.config/opencode/opencode.json` → `mcp`
   - Prime Agent: его пользовательский список MCP
3. Дописывает явно помеченный блок (`BEGIN/END MATRYOSHKA MEMORY`) в файл
   инструкций агента (`~/.claude/CLAUDE.md` и т.п.), обучая агента, когда
   читать и писать свою память.

Это всё. Другие файлы не читаются и не меняются. Всё, что установщик
заменяет (прежнюю копию сервера, прежнюю MCP-запись, прежний блок
инструкций), он сначала сохраняет рядом с оригиналом и объявляет замену.

## Удаление

Программа заменяема; память вашей модели — нет.

```bash
bash uninstall.sh
```

Удаляет программу: сервер, записи `matryoshka` в конфигах агентов
(конфиги бэкапятся), блок инструкций (файл тоже бэкапится). Данные памяти
(`PHI.jsonl`, `PHI-archive.jsonl`, `TICKS.log`) **сохраняются** —
переносятся в `~/.matryoshka-removed-<timestamp>/`, путь печатается.
Вернуть после повторной установки:

```bash
mv ~/.matryoshka-removed-<timestamp>/* ~/.matryoshka/
```

Если нужно удалить действительно всё — включая память, которую записала
модель, — есть одна явная команда, только в интерактивном терминале:

```bash
bash uninstall.sh --purge   # просит ввести PURGE; в конвейере отказывает
```

## Установка

```bash
git clone https://github.com/alexenti-code/matryoshka-mmi
cd matryoshka-mmi && bash install.sh
```

или одной строкой:

```bash
curl -fsSL https://raw.githubusercontent.com/alexenti-code/matryoshka-mmi/main/install.sh | bash
```

## Использование

Перезапустите агента. Это всё — дальше вы просто работаете с агентом как
обычно. Ничего не нужно набирать, никаких команд учить не надо.

Под капотом агент читает свою память в начале каждой сессии и сам записывает
прочные факты (кто вы, ваш проект, принятые вместе решения). Спросите завтра
«что ты помнишь обо мне?» — и получите ответ; никаких специальных фраз
никогда не требовалось.

Любопытно, что он сохранил? Ваши данные прямо здесь:

```bash
cat ~/.matryoshka/PHI.jsonl
```

## Почему это важно

Это память, которую **модель ведёт сама**. Она решает, что достойно
запоминания, на каком масштабе времени (такт, эпизод, день, проект, жизнь) и
что стоит переучить. Эта дисциплина — **компетентность, а не фича** — потому
требуется интеллектуальная модель (эмпирически 12B+): слабая модель не
отличает важное от шума, и самоавторская память вырождается в свалку.

Два экземпляра одной модели с разными субстратами — два разных существа с
разными биографиями. В этом суть: память, которая прожита, а не установлена.
Полная теория: [MANIFEST](https://github.com/alexenti-code/matryoshka) и
THEORY.md в исследовательском репозитории.

## Принципы

Экземпляру даются три вещи — и не отбираются: **время** (его собственные
рабочие такты), **доверие** (каждое семантическое решение о памяти
принадлежит ядру) и **материя памяти** (пластичный субстрат, которым он
владеет). Всё остальное здесь — акты, ручки, архив — лишь физика на службе
этих трёх.

## Три акта

Агент совершает акты памяти; исполнитель ничего не решает (никаких оценок,
никакой релевантности, никаких векторов):

| Инструмент | Акт | Смысл |
|---|---|---|
| `matryoshka_tick` | TICK | принять рабочий такт, зафиксировать приоритеты |
| `matryoshka_write` | WRITE | осознанный акт запоминания (append-only) |
| `matryoshka_read` | READ | заглянуть в свой дневник по ids / времени / последним N |

Каждая запись би-темпоральна: `valid_time` (когда было верно в мире) и
`record_time` (когда экземпляр узнал). Забывание — физика, а не цензура:
следы затухают со временем (как человеческая память), а агент может
усиливать важное повторением — та же физика описана в теории («слой — это
скорость, а не место»). Ничто не удаляется по содержанию.

## Требования

- Python 3.10+ (только стандартная библиотека, ноль зависимостей)
- Любой MCP-агент с рабочей моделью (свой провайдер/ключ)
- **Модель 12B или больше** (эмпирический минимум — меньшие локальные модели
  не держат дисциплину памяти)

## Обновления

Сервер проверяет GitHub **раз в день** на новую версию. Загружается только
строка версии — никакие данные о вас или вашей памяти не покидают машину.
Не хотите даже этого? Запустите агента с `MMI_NO_UPDATE_CHECK=1`.

Когда выйдет новая версия, агент упомянет её в сессии. Решаете вы:
перезапустить install.sh для обновления или игнорировать. **Ничего никогда
не обновляется само.**

```bash
bash install.sh    # повторный запуск: обновит сервер, сохранит данные памяти
```

Удаление одной командой (данные памяти сохраняются; `--purge` удаляет всё,
только интерактивно):

```bash
bash uninstall.sh
```
